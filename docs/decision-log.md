## D13 — Code format

| Item | Format | Example |
| --- | --- | --- |
| Module | Level letter + Category letter + 2-digit number | `FM01` |
| Unit | Module code + `-U` + 2 digits | `FM01-U01` |
| Lesson | Unit code + `-L` + 2 digits | `FM01-U01-L01` |
| Unit Quiz | Unit code + `-Q` + 2 digits | `FM01-U01-Q01` |
| Module End Test | Module code + `-MET` | `FM01-MET` |

Rules:

* Admins never type or edit codes. The module form has no code field.
* Codes do not change when items are reordered or edited. Display order is stored separately.
* Lists show the short part (M01, U03); detail pages and exports show the full code.

## D17 — Module status

| Status | Meaning |
| --- | --- |
| Draft | New module, never published. Only admins can see it. |
| Published | Students and teachers can see it. |
| Unpublished | Was published, now hidden. |

Rules:

* To publish, a module needs at least 1 unit with at least 1 lesson.
* The toggle in the module list switches between Published and Unpublished.
* A module can never go back to Draft once it has been published.
* When a module is unpublished, new students can't start it.
* Students already in an unpublished module keep their progress. It all comes back when the module is published again.

## D18 — Deleting content

Draft module (never published):

* Admin can delete the module, or any unit, lesson or quiz in it.
* It can be deleted even if it has content under it.
* A popup first shows what will be deleted, for example "3 units, 12 lessons".

Published or Unpublished module:

* The module can't be deleted. Unpublish it instead.
* A unit, lesson or quiz inside it can be deleted only if no student has started it.
* If a student has started it, the Delete button is disabled with the message "Students have started this; unpublish instead."

Questions:

* A question used in any quiz can't be deleted.
* Remove it from those quizzes first, then delete it.

## D19 — Downloads

* Downloadable files: PDF, audio and images only.
* No editable files (Word, PowerPoint) for students or teachers.
* Every download is logged: who, which file, when.
* No watermark in the first release. Add it later if logs show files being shared.

## D22 — Scoring

* Multiple choice: one correct answer only (first release).
* Points are set by the system, not typed by the admin (27 Oct 2026). Every scored item is worth 1 point, so scores are always whole numbers.
* Multiple choice, True/False and single-blank: 1 point, all or nothing.
* Matching, sequence and multi-blank: 1 point per pair, step or blank, with partial credit. Example: 3 of 4 pairs correct = 3 / 4 points.
* The question form shows the points read-only (e.g. "5 · 1 per step"). The import sheet has no Points column.

## D23 — Fill-in-the-blank

* Admin types `___` (three underscores) or uses "Insert blank" where each blank goes. Blanks show as numbered boxes, and the form shows one answer row per blank.
* Each blank can have several accepted answers (for example spelling variants), each entered as its own chip. No separator character is needed. Any of them is correct.
* Ignored when marking: extra spaces, invisible characters, upper/lower case in English.
* Not ignored: Myanmar vowel signs and tone marks. A wrong mark is a wrong answer.
* Zawgyi input is converted to Unicode before checking.

## D24 — Quiz attempts

Unit Quiz (practice):

* Unlimited attempts. The student can retry straight away.

Module End Test:

* 3 attempts.
* After 3 fails, the test locks for 24 hours. The screen says "Try again tomorrow. Review the lessons first" with links to the units.
* After 24 hours the student gets 3 more attempts. This repeats; there is no permanent block.
* Admin can unlock early from the student's account page.

Score:

* The best score counts. A later lower score never removes a pass, badge or certificate.

The numbers (3 attempts, 24 hours) are the starting defaults and may become admin settings later.

## D25 — Lesson completion

* The student must open every student-view file in the lesson (video, audio, PDF, images). Each file shows a tick once opened.
* Then the "Finish lesson" button turns on. Pressing it completes the lesson and unlocks the next one.
* Opening a video counts. Watching to the end is not required.
* Downloadable worksheets do not need to be opened.

## D26 — Progress percentage

* Progress counts steps: lessons + Required quizzes + the Module End Test.
* Progress = completed steps ÷ total steps.
* Example: 10 lessons + 2 Required quizzes + 1 Module End Test = 13 steps. 5 lessons and 1 quiz done = 6 ÷ 13 = 46%.
* 100% only when the Module End Test is passed (same moment as badge and certificate).
* The same number is shown on the student dashboard, admin user page and reports.

## D27 — Bulk import

Import is done per level, from that level's list page. Unit and lesson imports can cover many modules in one file (7 Oct). Each import screen has a **Download template** button.

| Level | Where | How |
| --- | --- | --- |
| Modules | — | No import. Use the normal form. |
| Units | Unit list page → Import units | Excel: module code, unit no., title, description. One file can cover many modules. |
| Lessons | Lesson list page → Import lessons | Excel: unit code (e.g. FM01-U01), lesson no., title, description. One file can cover many units. (Unit code, not module + unit no., because codes never change, even after reordering; 8 Oct) |
| Lesson files | Inside a lesson (normal lesson screen) | **Not imported.** Files need captions and per-file settings, so they are added on the normal lesson screen. (7 Oct) |
| Questions | Question list page → Import questions | Excel (one sheet per question type) + zip of images/audio. First column **Unit code** (e.g. FM01-U01), required: every question belongs to a unit. One file can cover many modules; with media, upload one module at a time (zip limit, e.g. 200 MB, to confirm). (8 Oct) |

Rules:

* Media files go in a zip and are referenced by exact file name (e.g. cat.png).
* Multiple choice and Matching options can have text, an image, or both.
* Questions use **one Excel file with one sheet per type** (not a separate import per type). Empty sheets are skipped, so one upload covers a unit's mixed questions. (7 Oct)
* Every question sheet starts with the same columns: Unit code, Points, Question prompt, Question media (matching the database fields). The type's own columns follow. (7–8 Oct)
* Every import is checked first and shows errors by sheet and row. Nothing is saved if any row has an error.
* New content is created as Draft; codes are created by the system.
* Codes are not shown on the Check screen. They are given at save time (next free number, inside the same all-or-nothing save), so they are always unique. Codes of deleted items are never reused. (7 Oct)
* The module (and unit, for lessons) must already exist: create modules with the form, import units before lessons. The Check screen shows an error for a code that is not found or a number already used. (7 Oct)
* Codes in the file are checked with one database lookup for the whole file, never row by row, so large files stay fast. (7 Oct)
* Quizzes are not imported; they are built on screen.
* Build order: after the normal create/edit screens. Questions import first, then units and lessons.

Admin flow (in the order a module is built):

1. **Units:** Unit list page → Import units → popup: Download template, upload Excel → Check (grouped by module; row, unit no., title) → units appear in the unit list as Draft, with their codes.
2. **Lessons:** Lesson list page → Import lessons → same popup and check → lessons appear in the lesson list as Draft, each with "Add files".
3. **Lesson files:** not imported. Open each lesson and add files on the normal lesson screen (with caption, Student/Teacher, Downloadable).
4. **Questions:** Question list page → Import questions → Download template, fill Unit code on each row, upload Excel + zip → Check (errors by sheet and row, or preview) → Import.
